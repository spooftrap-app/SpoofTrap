## 2024-06-29 - Fix command injection in UpdateChecker relaunchApp
**Vulnerability:** The `UpdateChecker` uses string interpolation to pass the application bundle path to a `/bin/sh -c` shell command. Since macOS application bundle names can be modified by the user, a maliciously named application directory (e.g., `SpoofTrap"; rm -rf /; ".app`) could lead to arbitrary command execution with the user's privileges when the application updates and restarts.
**Learning:** String interpolation in shell scripts (`/bin/sh -c`) using `Process.arguments` still constitutes shell execution. Bypassing standard argument arrays for `-c` exposes the application to command injection if any interpolated variable is user-controlled, even indirectly like the application bundle name.
**Prevention:** When using `/bin/sh -c` with `Process`, pass user-controlled variables or paths as separate positional arguments to the shell script (e.g., `$1`) instead of interpolating them, and delimit them using `--` (e.g., `["-c", "sleep 1 && /usr/bin/open \"$1\"", "--", appPath]`).
