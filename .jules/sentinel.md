## 2024-05-15 - [CRITICAL] Command Injection in Shell Process Execution via String Interpolation
**Vulnerability:** The application was using `Process()` to execute shell commands (`/bin/sh -c`) and passing dynamically obtained variables like the application's path directly into the command string via interpolation (`"sleep 1 && open \"\(appPath)\""`). This creates a command injection risk since the application path could potentially contain malicious characters (like semicolons or backticks).
**Learning:** Even internal variables or paths controlled seemingly by the system (like `Bundle.main.bundleURL.path`) should not be trusted if an attacker can manipulate the application's location or name before launch. When using `/bin/sh -c` with `Process()`, strings interpolated into the script string are evaluated by the shell.
**Prevention:** Never use string interpolation to construct shell commands when user-controlled or environment-controlled variables are involved. Instead, structure the script to use positional arguments (`$0`, `$1`, etc.) within the `-c` string, and pass the variable data separately as subsequent arguments in the `arguments` array (e.g., `["-c", "sleep 1 && /usr/bin/open \"$0\"", appPath]`). This ensures the shell treats the variable strictly as data, not executable code.
